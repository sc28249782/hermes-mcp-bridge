# v1.2.8 — deployment decision packet (released 22 October 2026; deployment decision pending)

วันที่: 22 ตุลาคม 2026.
สถานะ: **proposal รอ operator decision — ไม่มีการอนุมัติ deployment แฝงในเอกสารนี้**. เอกสารนี้เป็น preparation เท่านั้น: ไม่มีการหยุด/สลับ/รีสตาร์ต process, ไม่มีการเขียน config/state, ไม่มีการติดตั้ง runtime, ไม่มีการเริม backend job. Production ยังคง signed v1.2.7 จนกว่า operator จะอนุมัติและ deployment ดำเนินการตามแผนนี้.

## Preflight findings (read-only, 22 ตุลาคม 2026 — ตรวจแล้วจริง ไม่ใช่แผน)

- Production instance รันจาก `~/hermes-mcp-bridge-v1.2.7/bridge.py` ด้วย `.venv` Python **3.12.3**; Dev instance (`~/hermes-mcp-bridge-opencode-dev`, pin `e7add7e`) รันแยกอยู่ — ไม่สลับ
- `requirements-lock.txt` และ `requirements.txt` ของ deployed v1.2.7 **ตรงกับ tag v1.2.8 ทุก byte**; interpreter เดียวกับ suite receipts → เงื่อนไข "install ด้วย interpreter/locked deps เดิม" ตรวจแล้วผ่าน
- `bridge-config.json` mode 0600, `state/` mode 0700; state มี SQLite หลายไฟล์ที่กำลังถูกใช้ live — **ห้ามคัดลอกขณะ process ยังรัน**
- `~/hermes-mcp-bridge-v1.2.8` บนเครื่องคือ **git clone สำหรับ signing ของ operator — สงวนไว้ ห้าม overwrite/repurpose/delete**; deployment ต้องใช้ directory ใหม่ชื่อไม่ชนกัน (ตรวจซ้ำ ณ เวลาทำจริง)
- สถานะ job ปัจจุบันไม่ได้ตรวจใน preflight นี้ (อ่านจาก `bridge_status`/parent connector ณ เวลา deployment เท่านั้น) — ไม่อนุมานจากอายุ process

## แผน deployment (ตัวเลือก ก — ทำเมื่อ operator อนุมัติแล้วเท่านั้น)

1. **Install (ยังไม่ switch):** สร้าง directory ใหม่ชื่อไม่ชน (เช่น `hermes-mcp-bridge-v1.2.8-deploy`; ตรวจ `~/hermes-mcp-bridge-v1.2.8*` ก่อนตั้งชื่อ). ดาวน์โหลด assets จาก GitHub Release ลง directory ใหม่ รัน `sha256sum -c SHA256SUMS` ต้อง `OK` ตรง pins ข้างบน, `unzip -t` ต้องไม่มี error. ตรวจ checksum ตรง [release record](V1.2.8-RELEASE-RECORD-TH.md) ก่อนแตกไฟล์; ถ้าไม่ตรง หยุด ไม่แตกไฟล์.
2. สร้าง `.venv` ใน deployment directory ด้วย interpreter เดียวกับ production (Python 3.12.3) และติดตั้ง `requirements-lock.txt` ที่ตรงกัน (ตรวจ diff กับ deployed v1.2.7 ต้องว่าง). รัน `./bridge.sh version` จาก directory นี้ ต้องได้ identity `1.2.8`/`v1.2.8`/`release`/`release-archive`/`887436f...`/discovery 27 ครบ; ไม่ครบให้หยุด.
3. **Quiescence gate:** ตรวจ bounded job metadata ผ่าน `bridge_status` (สถานะ/จำนวนงานเท่านั้น ไม่อ่าน prompt/output). พบ active/nonterminal/unknown job **ให้บล็อกการสลับ** — ไม่ cancel, ไม่สันนิษฐาน terminal จากอายุ. รอ job resolve แล้วตรวจซ้ำ.
4. **Control plane handoff:** production connector ที่กำลังรัน control job หยุดตัวเองไม่ได้ เลือกหนึ่งอย่างชัดเจน: (i) operator รันขั้น stop/switch ใน terminal ของตนเอง หรือ (ii) Dev control ที่ผ่านการ verify อิสระ พร้อม restoration checks ชัดเจน. **ห้ามตัด parent control กลาง job**; ทาง Dev ต้องเปิดใช้แบบ explicit ไม่ activate อัตโนมัติ.
5. **Stop แบบ exact identity:** หยุด process ที่ args ระบุ path `~/hermes-mcp-bridge-v1.2.7/bridge.py` ตรงเป๊ะ (ไม่ substring match) เมื่อ job หมดแล้วเท่านั้น.
6. **Backup หลัง quiescent:** คัดลอก config/state หลังหยุดแล้ว เก็บเป็น private backup mode 0600/0700; ตรวจ integrity (เทียบ hash ก่อน/หลังคัดลอก); **ไม่มี DB merge, ไม่มี replay, ไม่มี resubmit**.
7. **Switch และ restart:** เปลี่ยน launch ไปที่ directory ใหม่แล้ว restart ผ่าน auth flow เดิม; คง config เดิมทุกค่า (รวม OpenCode opt-in ถ้าเปิดอยู่); Dev pin `e7add7e` ไม่ถูกสลับ.
8. **Post-switch scoped acceptance:** รันตรวจด้านล่างทั้งหมด; fail ข้อใดถือเป็น rollback trigger.

ข้อจำกัดหลักฐาน: §21 acceptance เดิมเป็น mock-backend evidence เท่านั้น; post-switch นี้ไม่ขยายเป็น real-backend/native acceptance และไม่อ้าง migration acceptance.

## Rollback

- Baseline: signed v1.2.7 deployment เดิม (คง directory/backup ไว้ตั้งแต่ deployment 21 ตุลาคม 2026)
- Triggers: identity ไม่ตรง, health/status fail, registry unavailable, acceptance fail, หรือ error ที่น่าเชื่อถือใดๆ หลัง switch
- ขั้น: หยุดรับงาน ตรวจ active jobs/process ก่อน; หยุด instance v1.2.8 เมื่อปลอดภัย; คืน launch เป็น v1.2.7 แล้ว restart ผ่าน auth flow เดิม
- หากมีการเขียน state ใหม่เกิดขึ้นหลัง switch: เลือก snapshot ใหม่**หลังตรวจผลกระทบ** — ห้าม restore state เก่าตาบอด, ห้ามรวม DB, ห้าม replay งาน
