# แผนพัฒนา v1.2.4 — MCP Events สำหรับสถานะงาน Hermes

## สถานะ

แผนนี้เป็น **capability-gated** และจัดลำดับก่อน v1.3.0 เพื่อแก้ปัญหาการรอผลของงาน Hermes ใน ChatGPT Work chat ไม่มี commitment ด้าน runtime จนกว่า capability gate จะผ่านครบ

v1.3.0 Local Hands mutation/execution ถูกพักไว้ ไม่มีการเพิ่ม `hands_write`, `hands_patch`, `hands_exec` หรือ capability ใหม่ใน v1.2.4

## เป้าหมาย

เมื่อผู้ใช้เลือกติดตามงาน Hermes ใน Work chat, ChatGPT ต้องรับ event ที่ลงลายเซ็นจาก bridge เมื่อ run นั้นเข้าสู่ terminal state แล้วทำตามคำสั่งของผู้ใช้ใน chat เดิมได้

ระบบนี้ไม่ใช่การส่ง notification ไปทุก chat และไม่ใช่ background polling โดย bridge

## ขอบเขตของ release

- รองรับ event เดียว: `hermes.run.terminal`
- filter ต้องระบุอย่างน้อยหนึ่งค่า: bridge-owned `run_id` หรือ explicit `context_id`
- terminal status ที่ส่งได้คือ `completed`, `failed`, `cancelled`, หรือสถานะ terminal อื่นที่ bridge บันทึกไว้จริง
- payload มีเฉพาะ `event_id`, `run_id`, `context_id` เมื่อมี, `status`, เวลา terminal, `result_available`, และ reason code ที่ redacted
- ChatGPT ใช้ `hermes_task_result` ที่มีอยู่เพื่ออ่านผลเต็มหลังได้รับ event
- MCP tool discovery ยังคง 27 tools; event capability ไม่ใช่ MCP tool

## Session-model continuity regression

ผลตรวจ code path ของ Hermes context ชี้ว่า follow-up ที่ resolve จาก `context_id` ต้องส่งเพียง input และ persisted `session_id`; bridge ปฏิเสธ model/provider/model-options override บน follow-up อยู่แล้ว ส่วน `reported_model` คือ observation metadata จาก upstream ไม่ใช่ช่องเลือก model

v1.2.4 ต้องเพิ่ม regression test แบบ context integration เพื่อพิสูจน์สองข้อข้างต้นพร้อมกัน และเพิ่มข้อความอธิบายในเอกสาร operator เพื่อไม่ให้ผู้ใช้ตีความชื่อ generic ที่ upstream รายงานเป็นการเปลี่ยน model

## นอกขอบเขต

- Codex completion events
- Hermes approval events, automatic approvals, หรือการตอบ approval ผ่าน event
- content, prompt, output, credential, path รายละเอียด, หรือ model transcript ใน event payload/audit
- polling, streaming, push ไปยัง Windows desktop/mobile, หรือการแจ้งทุก chat
- Local Hands mutation/execution และงาน v1.3.0 ทั้งหมด

## ข้อกำหนดและ security invariants

1. Feature ปิดโดย default ด้วย `events.enabled=false`; ไม่มี outbound callback จนกว่าจะเปิดอย่างชัดเจน
2. ต้องใช้ MCP Events protocol 2.0 (`2026-07-28`) และประกาศ `events` capability พร้อม `events/list`, `events/subscribe`, และ `events/unsubscribe`
3. รองรับ webhook delivery เท่านั้น; subscription ต้องผ่าน callback verification ก่อน active
4. callback URL ต้อง match exact host หรือ host suffix ใน allowlist ที่ operator ตั้งผ่าน config เท่านั้น; default allowlist ว่าง. ค่า allowlist ที่ใช้จริงต้องมาจากผล Dev capability probe ไม่ใช่ model, prompt, หรือ subscription payload
5. HTTPS-only, ปฏิเสธ private/local address และ redirect, และยึด address ที่ตรวจแล้วสำหรับการเชื่อมต่อ เป็น defense-in-depth เพิ่มจาก allowlist ไม่ใช่การอนุญาตด้วย deny-list
6. subscription รับได้เฉพาะ MCP Events protocol call ที่ authenticated ผ่าน tunnel principal หลังผู้ใช้ยืนยันใน Work chat; ห้ามมี MCP tool/CLI สำหรับให้ model สร้าง callback URL หรือ subscription เอง
7. เก็บ subscription, callback URL, signing secret, owner/filter, cursor และ expiry แบบ persistent ใน state directory ที่ mode 0700; DB/blob ที่เกี่ยวข้องต้อง mode 0600
8. signing secret และ callback URL ห้ามเข้า audit log, tool result, diagnostics หรือ event payload
9. subscription ต้องผูกกับ principal ที่ authenticated และตรวจว่า run/context เป็น bridge-owned ก่อน subscribe, refresh, deliver หรือ unsubscribe
10. ใช้ event ID คงเดิมในการ retry; delivery ซ้ำต้อง idempotent และ payload จำกัดขนาด
11. event ส่งได้หลัง bridge บันทึก terminal record ที่ recoverable แล้วเท่านั้น; ห้าม infer completion จาก tool event กลางทาง
12. delivery failure ห้ามเปลี่ยนสถานะงาน Hermes และห้ามทำให้ผลลัพธ์สูญหาย

## Capability gate ก่อน implementation

ก่อนเปิด PR โค้ด ต้องพิสูจน์ทั้งสามข้อบน Dev tunnel:

1. tunnel-client และ Secure MCP Tunnel รองรับ MCP Events protocol/HTTP methods ที่ต้องใช้
2. WSL2 สามารถส่ง HTTPS callback ไปยัง callback URL ที่ ChatGPT มอบให้ได้ตาม policy **และตรงกับ allowlist ที่ operator ตั้ง** โดยไม่เปิด inbound public service
3. Work chat ที่ใช้ plugin สามารถ discover, subscribe, รับ webhook ที่ลงลายเซ็น และ unsubscribe ได้จริง

หากข้อใดไม่ผ่าน ให้บันทึกผลและหยุดก่อน implementation ไม่สร้าง fallback polling ปลอมเป็น push

## ทางเลือกที่โปร่งใส: explicit polling

หาก capability gate ไม่ผ่านหรือ operator ไม่เปิด events ผู้ใช้ยังเรียก `hermes_task_status` และ `hermes_task_result` จาก ChatGPT โดยตรงได้ การ polling ที่ ChatGPT/ผู้ใช้สั่งอย่างชัดเจนเป็นทางเลือกที่ถูกต้อง แต่ต้องไม่ถูกเรียกว่า push notification และไม่ทำงานแบบซ่อนอยู่ใน bridge

## การออกแบบ persistence

ใช้ namespace ใหม่ `state/events.sqlite3` แยกจาก Hermes/Codex/context state

ขั้นต่ำของ subscription record:

- deterministic `subscription_id`
- authenticated owner identifier
- event name และ canonical filter
- callback URL และ signing secret
- status, created/updated/expires/refresh-before
- last delivery cursor และ event-id deduplication ที่ bounded

subscription หมดอายุต้องหยุด delivery และลบ/หมุน secret ตาม retention policy โดย audit เฉพาะ metadata ที่ redacted

## ลำดับ PR

1. **PR-1: capability probe + SPEC amendment** — เอกสาร protocol, threat model, config, callback validation, privacy contract, และ Dev-tunnel feasibility; ไม่มี runtime event delivery
2. **PR-2: subscription protocol and state** — `events/list/subscribe/unsubscribe`, persistent state, authorization, TTL/refresh, callback challenge; ไม่มี terminal delivery
3. **PR-3: Hermes terminal delivery** — observer ของ terminal record, signed webhook, retry/idempotency, bounded redacted payload และ local diagnostics
4. **PR-4: tests and live acceptance** — fake callback, malformed/SSRF callback denial, signature/challenge, restart/expiry/dedup/retry, WSL2 Dev-tunnel end-to-end, docs/update/review/release gates

ทุก PR ต้องรักษา v1.2.3 behavior เมื่อ `events.enabled=false`

## Acceptance criteria

- ผู้ใช้สั่ง monitor ใน Work chat แล้ว ChatGPT subscribe ได้
- run Hermes ที่ completed/failed/cancelled ส่ง event เดียวที่ตรวจลายเซ็นผ่าน
- ChatGPT รับ event ใน chat ที่ subscribe และเรียก result ได้ตามคำสั่งผู้ใช้
- restart bridge ไม่ทำ subscription/event record สูญหายหรือส่ง event ซ้ำโดยไม่มี deduplication
- callback ที่ HTTP, redirect, private/local address, signature ไม่ถูกต้อง หรือ owner/filter ไม่ตรง ถูกปฏิเสธ
- audit, diagnostics, events และ tool results ไม่มี prompt/output/credential/callback secret
- disabled configuration ไม่มี outbound callback และไม่มี behavior regression
- independent review, WSL2 live acceptance, docs gate และ release Phase A/B/C ผ่านก่อน tag
